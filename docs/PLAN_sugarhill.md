## 0. 바로잡기

- 대상은 **슈가힐 신규 공장** (사용자가 직접 모델링한 공장). 습식장비가 아님.
- 그래서 AUDIT 문제 7번("Mode 1이 범용 CNC 공장이라 도메인 불일치")은 **철회**: 슈가힐 공장 안의 CNC·3D 프린터 설비를 다루는 현재 씬이 맞는 방향.
- 지난 작업 중 SEABatch 관련 산출물(`/seabatch`, `viewer/lib/wetbench_sim.js`, `tests/wetbench_sim.test.js`, `PLAN_roadmap.md`의 내부 자료 메모)은 **보류**. 삭제·보관 여부는 사용자 결정 (아래 7절).

## 1. 목표

슈가힐 공장을 웹에서 하나의 트윈으로:

1. **공간** — 실제로 찍은 공장 모습 (3DGS)을 배경으로
2. **정밀 형상** — 건물·구조·문·설비 배치를 치수 파라미터로 관리 (B-Rep, 측정 가능)
3. **설비 상태** — CNC·3D 프린터·화물문 상태를 가짜 PLC로 구동, 나중에 실제 데이터는 읽기 전용
4. **트윈 안에서 3D 모델링** — 공장에 들어갈 부품·지그·가구를 웹에서 만들고, 공장 씬에 배치해 간섭 확인, 3D 프린팅(STL)·CNC(DXF/G-code 초안)로 내보내기

### 지금 파라미터에서 바로 보이는 검증 거리 (예시)
- 메자닌 계단: 18단 × 180 mm = **3,240 mm**, 플랫폼 높이 **3,200 mm** → 40 mm 불일치. 실제 값 확인 필요.
- 이런 불일치를 자동으로 잡는 것이 S2의 "파라미터 ↔ STEP 측정 리포트".

## 3. 구조 (한 장 요약)

```
[촬영 영상] → 3DGS (배경, 측정 기준 아님) ──────────┐
                                                     │ 기준점 3~4개로 정합
[layout_spec.json 파라미터 표] → SolidCraft → STEP(B-Rep) ─→ 측정 리포트(파라미터 대조)
                                    │
                                    └→ 웹 표시용 메쉬(glTF/OBJ) ──→ /v2 공장 씬
[가상 PLC: CNC·3D프린터·화물문] → 태그 → 대시보드  (실제 연동은 읽기 전용, 나중)
[웹 모델링] 빠른 스케치(메쉬) / 정밀 모드(파라미터→SolidCraft→STEP)
        → 공장 씬 배치·간섭 확인 → STL(3D프린팅) / DXF→Skyline 네스팅→G-code 초안
```

원칙: **치수의 기준은 파라미터 표 하나**. 웹·3DGS·메쉬는 보여주기만 한다.

| 단계 | 내용 | 완료 기준 (테스트로 증명) | 모델 |

## 5. S2를 먼저 하는 이유
- 지금 가장 큰 거짓 주장은 "정밀"인데, 정밀의 근거가 될 파라미터 표와 B-Rep STEP이 이미 있음. 둘을 측정으로 연결하기만 하면 됨.
- 이후 모든 단계(웹 표시, 3DGS 정합, 부품 배치 간섭)가 이 기준 좌표에 의존.

## 6. 3DGS 재촬영이 필요할 때 (사용자 메모 기준)
- 휴대폰 4K 30fps, 줌 금지, HDR 끔, 노출·포커스 고정, 천천히 걷기, 높이 3단, 겹침 70~80 %, 방 하나 200~500장.
- 2 fps 프레임 추출 → COLMAP → 3DGS (Colab T4). 여러 번 찍은 데이터는 겹침 30 % 이상·같은 조명일 때만 합침.
- 흰 벽·반사 금속·유리 구간 주의. 움직이는 공정은 3DGS로 하지 않음(4DGS는 다카메라 필요).

## 7. 사용자 확인이 필요한 것
1. **슈가힐 실제 치수 자료**가 있는지 (DWG/PDF 도면, 실측 메모). 없으면 `layout_spec.json`을 기준으로 진행하고 "모델 치수(실측 미확인)"로 표기.
2. 공장 안 **설비 목록** (CNC·3D 프린터 기종, 대수) — 현재 씬의 설비가 실제와 같은지.
3. SEABatch 산출물: ① 삭제 ② `archive/`로 보관 ③ 그대로 둠 — 어느 쪽?
4. 진행 순서: S1 → S2 그대로 갈지.
